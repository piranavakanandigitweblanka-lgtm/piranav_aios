Step-by-Step Installation

1
Connect to the Server via SSH

Open PuTTY on Windows. Enter the server IP and connect as root.

# PuTTY settings
Host: 158.220.99.127
Port: 22
Connection type: SSH
Login as: root
Always SSH as root on Contabo — the default user is root unless you created a separate account.
2
Update System & Install PostgreSQL

Run a full system update first, then install PostgreSQL 16 with contrib extensions.

# Update all packages
apt update && apt upgrade -y

# Install PostgreSQL 16 + contrib tools
apt install postgresql postgresql-contrib -y
On Ubuntu 24.04, apt install postgresql installs PostgreSQL 16 by default. The postgresql-contrib package adds useful extensions like pg_stat_statements.

Verify the Installation

# Check PostgreSQL version
psql --version
# Expected: psql (PostgreSQL) 16.x

# Check service is running
systemctl status postgresql
3
Start & Enable PostgreSQL Service

Make sure PostgreSQL starts automatically on server reboot.

# Start PostgreSQL now
systemctl start postgresql

# Enable on boot
systemctl enable postgresql

# Confirm both are active
systemctl status postgresql
# Look for: Active: active (running)
4
Create Database, User & Permissions

Connect as the postgres superuser and set up your app's database.

# Open psql as postgres superuser
sudo -u postgres psql

Inside psql, run these SQL commands:

-- 1. Create database
CREATE DATABASE dm_dashboard;

-- 2. Create app user with password
CREATE USER dm_user WITH PASSWORD 'your_strong_password_here';

-- 3. Grant full access to the database
GRANT ALL PRIVILEGES ON DATABASE dm_dashboard TO dm_user;

-- 4. Connect to the new database
\c dm_dashboard

-- 5. Transfer schema ownership to app user
ALTER SCHEMA public OWNER TO dm_user;

-- 6. Grant all schema privileges
GRANT ALL ON SCHEMA public TO dm_user;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO dm_user;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO dm_user;

-- 7. Create app role (optional but recommended)
CREATE ROLE dm_dashboard_app;
GRANT dm_dashboard_app TO dm_user;

-- Exit psql
\q
Step 5 (ALTER SCHEMA) is critical. Without it, your app user cannot create tables or write data even if they own the database. This is the most common permission error after a fresh install.
5
Test the Connection
# Test login as dm_user
psql -U dm_user -d dm_dashboard -h localhost -W
# Enter your password — you should get a psql prompt

# List all databases (inside psql)
\l

# List tables in public schema
\dt
If you get a dm_dashboard=# prompt — PostgreSQL is correctly installed and your user has access.
6
Restore Database from pg_dump Backup

If migrating an existing database from your local Windows machine:

On Your Local Windows PC

# Export from local PostgreSQL
# Run in Command Prompt or PowerShell
"C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U dm_dashboard_app -h localhost -p 5432 dm_dashboard -f dm_backup.sql

# If pg_dump is not in PATH, use the full path above

Upload via FileZilla

Protocol:   SFTP
Host:       158.220.99.127
Port:       22
Username:   root
Password:   [your Contabo root password]

Upload: dm_backup.sql → /root/dm_backup.sql

On the Server — Restore

# Copy to /tmp so postgres user can read it
cp /root/dm_backup.sql /tmp/dm_backup.sql
chmod 644 /tmp/dm_backup.sql

# Stop app service first (if running)
systemctl stop dm-dashboard

# Drop and recreate clean database
sudo -u postgres dropdb dm_dashboard
sudo -u postgres createdb dm_dashboard

# Restore from dump
sudo -u postgres psql -d dm_dashboard -f /tmp/dm_backup.sql

# Re-apply permissions after restore
sudo -u postgres psql -d dm_dashboard
-- Re-run after every restore
ALTER SCHEMA public OWNER TO dm_user;
GRANT ALL ON SCHEMA public TO dm_user;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO dm_user;
GRANT ALL PRIVILEGES ON ALL SEQUENCES IN SCHEMA public TO dm_user;
\q
Always re-apply schema ownership and grants after a restore. The dump file restores data but may reset ownership to postgres.
7
Configure App Connection String

In your backend .env file on the server:

# /var/www/dashboard-dm/backend/.env
DATABASE_URL=postgresql://dm_user:your_password@localhost:5432/dm_dashboard
Connection string format matters. Use postgresql:// — NOT postgresql+psycopg:// when using psycopg_pool. This caused a DB connection timeout in the original setup.

Troubleshooting

❌ ERROR: permission denied for schema public
✅ Fix: Run ALTER SCHEMA public OWNER TO dm_user; and re-grant all privileges. See Step 4.
❌ connection to server at "localhost" failed — Connection refused
✅ Fix: PostgreSQL not running. Run systemctl start postgresql.
❌ pg_dump: command not found (on Windows)
✅ Fix: Use full path — "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe"
❌ DB connection timeout in FastAPI app
✅ Fix: Change connection string from postgresql+psycopg:// to postgresql:// in .env.
❌ FATAL: role "dm_user" does not exist after restore
✅ Fix: Re-run Step 4 (CREATE USER + GRANT) after dropdb/createdb — the restore wipes roles.
❌ could not open file "/root/dm_backup.sql": Permission denied
✅ Fix: cp /root/dm_backup.sql /tmp/dm_backup.sql && chmod 644 /tmp/dm_backup.sql — postgres user cannot read /root.

Security Notes

Port 5432 is NOT open to the public on this server — external pgAdmin access is disabled. All DB connections are local only (app → localhost:5432). Do not open 5432 to the internet without SSL and strong firewall rules.
  • Never use the postgres superuser in your app's connection string
  • Use a dedicated app user (dm_user) with minimum required privileges
  • Store the DATABASE_URL in .env — never hardcode it in source code
  • Back up .env to /root/backend.env.backup — it is NOT in Git
  • Take a pg_dump before any major migration or schema change
